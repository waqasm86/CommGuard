# Applicant evidence notes

These notes are a technical evidence inventory, not application prose. They do
not answer selection questions, speak in an applicant's voice, or supply a
personal motivation narrative.

## Repository work that can be independently verified

- The SDK has explicit provenance, corpus membership, coverage, true-session
  grouping, central-protocol, benign-matrix, and bounded adversarial contracts.
- CPU-safe tests exercise failure paths without manufacturing GPU outcomes.
- Canonical Kaggle notebooks are output-free, pin remote-visible commits, chain
  only hash-verified immutable archives, and stop at scientific/human gates.
- The evidence index preserves an unfavorable historical primary result instead
  of promoting a tiny combined-feature diagnostic.
- The central-monitoring path is labeled as a local two-agent simulation; the
  physical deployment assumptions remain open work.

## Evidence a reviewer can inspect

- [`evidence-index.md`](evidence-index.md) for immutable artifact hashes and
  claim boundaries.
- [`current-results.md`](current-results.md) for the exact coverage failure and
  DDP-versus-idle negative result.
- [`acceptance-status.md`](acceptance-status.md) for completed versus pending
  validation.
- [`research-report-template.md`](../reports/research-report-template.md) for

Any personal interpretation, project-choice rationale, or application response
must be written by the applicant.
